# Milestone v1.0: CV Generator MVP

**Status:** SHIPPED 2026-01-23
**Phases:** 1-8
**Total Plans:** 33

## Overview

This roadmap delivered a CLI tool that generates ATS-optimized CVs from markdown. The phases were structured to build a stable foundation first (schema + parsing), then layer rendering capabilities (HTML, PDF, DOCX), then expand with CLI commands and IT professional features, and finally polish with multiple templates and documentation.

## Phases

### Phase 1: Foundation + Data Schema

**Goal**: Establish Bun monorepo with TypeScript, define CVData schema, and implement markdown parser with multi-language support.

**Depends on**: None (first phase)

**Plans**: 3 plans

Plans:
- [x] 01-01-PLAN.md — Project scaffolding (monorepo, TypeScript, Biome, LICENSE, .gitignore)
- [x] 01-02-PLAN.md — CVData schema (TypeScript interfaces for all sections)
- [x] 01-03-PLAN.md — Markdown parser (frontmatter + section extraction with language tags)

**Details:**
- TypeScript project compiles and runs with `bun run typecheck`
- CVData interface validates sample markdown with all basic sections
- Parser extracts structured data from markdown frontmatter and body
- Missing sections in input produce no errors and no empty sections in output

### Phase 2: Template Engine

**Goal**: Users can apply design templates to parsed CV data, producing intermediate HTML.

**Depends on**: Phase 1 (requires CVData schema and parser)

**Plans**: 3 plans

Plans:
- [x] 02-01-PLAN.md — Package scaffolding (@gottz/cv-templates, types, i18n)
- [x] 02-02-PLAN.md — Base template files (template.njk, styles.css, config.json)
- [x] 02-03-PLAN.md — Engine core (Nunjucks environment, filters, renderCV function)

**Details:**
- Template loader discovers templates from `/templates/` directory
- Nunjucks renders CVData into styled HTML with semantic structure
- Rendered HTML uses single-column layout with CSS/flexbox (no tables)
- Contact information appears in document body, not headers/footers

### Phase 3: HTML Output

**Goal**: Users can generate self-contained HTML files with fully embedded CSS and images.

**Depends on**: Phase 2 (requires template engine producing HTML)

**Plans**: 3 plans

Plans:
- [x] 03-01-PLAN.md — CLI scaffold (dependencies, console utilities, Commander.js entry point)
- [x] 03-02-PLAN.md — Image processing (Sharp-based processing, base64 encoding, HTML embedding)

**Details:**

## Milestone Summary

**Decimal Phases:**

None (all phases were delivered as planned, gap closure added as additional plans within existing phases)

**Key Decisions:**

- 8-phase structure: Comprehensive depth setting; let natural boundaries stand
- Sequential phases: Each phase builds on previous foundation
- HTML before PDF: Puppeteer uses HTML as intermediate format
- DOCX after PDF: Parallel capability but deferred to ensure HTML foundation
- Biome v2.3.11: Tabs for accessibility, exclude .planning from linting
- Standard fonts only: Arial, Helvetica for maximum ATS compatibility
- CSS-to-DOCX style extraction: Maintain visual parity across formats
- Configuration cascade: template defaults < global config < env vars < frontmatter

**Issues Resolved:**

- DOCX linebreak handling: TextRun break uses number (1) not boolean
- PDF pagination: Sections use break-inside: auto to allow spanning pages
- Spinner edge cases: Optional chaining for null spinner in quiet mode
- Commander --no-* flags: Need explicit definition and manual check

**Issues Deferred:**

None (all v1 requirements delivered)

**Technical Debt Incurred:**

None (no shortcuts or deferred work)
