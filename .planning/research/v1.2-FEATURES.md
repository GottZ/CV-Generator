# Feature Research: AI-Assisted CV Writing, CLI Wizards, and Template Generation

**Domain:** AI-enhanced CV generator CLI with interactive wizards
**Researched:** 2026-01-25
**Milestone:** v1.2 - AI and Interactive Features
**Confidence:** HIGH (verified across multiple sources, cross-referenced with official documentation)

---

## Executive Summary

This research covers three major feature areas for the v1.2 milestone:

1. **AI-Assisted CV Writing** - LLM-powered content generation for achievement bullets, summaries, job tailoring, and improvement suggestions
2. **Interactive CLI Wizard** - Interview-style guided CV creation and incremental updates
3. **Template Scaffolding** - User customization of templates through guided prompts

The research identifies clear table stakes (what users expect), differentiators (competitive advantages), and anti-features (what to deliberately avoid). A key finding is that AI features must prioritize user control and accuracy over automation, as 62% of employers reject AI-generated resumes without personalization.

## 1. AI-Assisted CV Writing Features

### 1.1 Table Stakes

Features users expect from AI-assisted CV tools. Missing these makes the AI features feel incomplete.

| Feature | Why Expected | Complexity | Dependencies | Notes |
|---------|--------------|------------|--------------|-------|
| **Achievement bullet generation** | Core AI value proposition; every AI CV tool offers this | Medium | LLM provider, CV schema | Generate impactful bullets from basic job descriptions |
| **Professional summary generation** | Second most common AI feature after bullets | Low | LLM provider | Create attention-grabbing summary from CV data |
| **Keyword optimization suggestions** | 97%+ Fortune 500 use ATS; users expect AI to help with keywords | Medium | Job description input, LLM | Identify missing keywords from job descriptions |
| **STAR method formatting** | Industry standard for achievement bullets | Low | LLM prompt engineering | Situation, Task, Action, Result structure |
| **Quantification suggestions** | AI should help add metrics where missing | Medium | LLM analysis | "Added sales" -> "Increased sales by 40%" |
| **Multi-provider support** | Users have different LLM preferences/access | Medium | Provider abstraction layer | OpenAI, Anthropic, local models (Ollama) |
| **Prompt export fallback** | Not all users have API keys; must work without | Low | Clipboard integration | Copy prompt to paste into ChatGPT/Claude web |
| **Preview before accepting** | Users must approve AI-generated content | Low | Interactive prompts | Never auto-write without confirmation |
| **Error handling for API failures** | LLM APIs are unreliable; must degrade gracefully | Low | Error handling | Clear messages, retry options, fallback to export |

**Complexity Notes:**
- Bullet generation is medium complexity due to prompt engineering and context handling
- Multi-provider support requires abstraction layer (consider LiteLLM or similar)
- Prompt export is low complexity but critical for accessibility

### 1.2 Differentiators

Features that set this tool apart from web-based AI resume builders.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **Job description tailoring** | Rewrite existing CV content for specific job postings | High | Parse JD, match to CV sections, suggest changes |
| **Batch improvement mode** | Analyze entire CV and suggest improvements in one pass | Medium | Comprehensive analysis rather than section-by-section |
| **Weak bullet detection** | Identify bullets lacking impact/metrics proactively | Medium | "Responsible for X" -> flagged for rewrite |
| **Before/after diff view** | Show exactly what AI changed | Low | Terminal diff or side-by-side |
| **Interview-style content extraction** | Ask questions to generate content ("Tell me about a time...") | High | Conversational flow, context tracking |
| **Local model support (Ollama)** | Privacy-focused, no API costs, works offline | Medium | Ollama API integration |
| **Tone adjustment** | Same content, different tone (formal, conversational, technical) | Low | Prompt parameter |
| **IT-specific prompt templates** | Prompts tuned for tech roles, projects, certifications | Low | Domain expertise in prompts |
| **Context-aware suggestions** | AI understands full CV, not just current section | Medium | Include relevant context in prompts |

**Differentiator Priority (Recommended):**

**High priority (build first):**
1. Job description tailoring - high user demand
2. Before/after diff view - critical for trust
3. Local model support - privacy differentiation

**Medium priority (build second):**
4. Weak bullet detection
5. Context-aware suggestions
6. IT-specific prompt templates

**Lower priority (consider later):**
7. Interview-style content extraction (complex UX)
8. Batch improvement mode
9. Tone adjustment

### 1.3 Anti-Features

Things to deliberately NOT build for AI features. Based on employer feedback and common mistakes.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| **Auto-write without preview** | 62% of employers reject AI content without personalization; trust issue | Always preview, require explicit approval |
| **Hallucinated credentials** | AI tools fabricate experience; legal/ethical issues | Never generate factual claims user didn't provide |
| **Keyword stuffing mode** | Modern ATS detects this; hurts human readability | Natural keyword integration only |
| **Full CV generation from scratch** | Produces generic, detectable AI content | Enhance existing content, don't fabricate |
| **Auto-submit to job boards** | Out of scope; API complexity; user control | Generate files only, user submits manually |
| **Real-time API calls during build** | Slows build, fails on network issues | AI commands separate from build command |
| **Store API keys in CV files** | Security risk | Separate config file or env vars |
| **Unlimited context windows** | Expensive, slow, often unnecessary | Smart context selection |

**Anti-Feature Rationale:**

From [Resume Now Survey](https://www.resume-now.com/job-resources/careers/ai-applicant-report): "62% of employers say resumes generated by AI without personalization often lead to candidate rejection."

From [Built In](https://builtin.com/articles/risks-ai-resume-builders): "AI-powered resume builders often fall short when it comes to helping job seekers in tech truly stand out... Worse, these resumes can be trained on poor data, which steers the resume in the wrong direction."

From [CNBC](https://www.cnbc.com/2025/09/15/dont-make-these-ai-mistakes-on-your-resume-career-experts-say-it-could-ruin-your-chances.html): "One job seeker didn't read her AI-edited resumes before sending them out, and later found that the AI tool had exaggerated her work experience and inserted inaccurate information."

## 2. Interactive CLI Wizard Features

### 2.1 Table Stakes

Features users expect from CLI wizards. Based on established patterns from AWS CLI, Angular CLI, and similar tools.

| Feature | Why Expected | Complexity | Dependencies | Notes |
|---------|--------------|------------|--------------|-------|
| **Non-interactive fallback** | Wizards must work in scripts/CI; POSIX convention | Low | Flag parsing | `--no-input` or detect non-TTY |
| **Input validation with clear errors** | Users shouldn't complete wizard then fail on bad input | Low | Zod/schema validation | Validate as-you-go, not at end |
| **Sensible defaults** | Reduce typing, guide inexperienced users | Low | Default values in prompts | Pre-fill with common choices |
| **Escape mechanism (Ctrl+C)** | Users must be able to exit cleanly | Low | Signal handling | Clear exit, no partial state |
| **Summary before commit** | Review all inputs before creating files | Low | Display collected data | "You entered X, Y, Z. Proceed?" |
| **Password/key masking** | API keys should not echo to terminal | Low | TTY control | Use `type: 'password'` prompts |
| **Arrow key navigation** | Modern CLI expectation for selection | Low | Inquirer.js | List, checkbox prompts |
| **Progress indication** | Long operations need feedback | Low | Ora/spinner | "Generating..." spinners |
| **Help text per question** | Users need context without leaving wizard | Low | Prompt descriptions | Inline help, not just --help |

**Complexity Notes:**
- Most wizard table stakes are low complexity because Inquirer.js handles them
- Non-interactive fallback is critical for CI/CD usage

### 2.2 Differentiators

Features that make the wizard experience exceptional.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **Partial completion resume** | User can exit and continue later | High | State persistence to file |
| **Incremental CV updates** | Wizard for adding single job, not full CV | Medium | Detect existing CV, add section |
| **Fuzzy template search** | Type partial name, find template | Low | Already exists in codebase |
| **Contextual follow-up questions** | "You mentioned X, tell me more about Y" | High | State machine, conditional prompts |
| **Multi-step undo** | Go back multiple steps, not just one | Medium | Navigation state tracking |
| **Preview at any step** | See current CV state mid-wizard | Medium | Render partial CV |
| **Import from LinkedIn/JSON Resume** | Start wizard with existing data | Medium | Parser for external formats |
| **Guided achievement prompts** | "What was the business impact?" style questions | Low | STAR-method prompts |
| **Section-specific wizards** | `wizard add experience` vs full wizard | Low | Subcommands |

**Differentiator Priority (Recommended):**

**High priority (build first):**
1. Section-specific wizards - most practical for incremental updates
2. Guided achievement prompts - aligns with AI features
3. Fuzzy template search - already implemented, extend to wizard

**Medium priority (build second):**
4. Incremental CV updates
5. Multi-step undo
6. Preview at any step

**Lower priority (consider later):**
7. Partial completion resume (complex state management)
8. Import from LinkedIn/JSON Resume
9. Contextual follow-up questions

### 2.3 Anti-Features

Things to deliberately NOT build for wizards.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| **Mandatory wizard for existing users** | Power users want flags, not prompts | Wizard optional, flags always work |
| **Wizard for build command** | Build is already simple, wizard adds friction | Wizard for init/add, build stays simple |
| **Web-based wizard UI** | Explicitly out of scope; adds massive complexity | CLI-only wizard |
| **Real-time collaboration** | Out of scope per PROJECT.md | Single-user workflow |
| **Cloud-saved wizard state** | Privacy concerns; out of scope | Local file only |
| **Required account/login** | Explicitly out of scope | Local-only tool |
| **Animated wizard graphics** | Terminal compatibility issues; distracting | Simple text, spinners only |

## 3. Template Generation Features

### 3.1 Table Stakes

Features users expect from template scaffolding/customization.

| Feature | Why Expected | Complexity | Dependencies | Notes |
|---------|--------------|------------|--------------|-------|
| **List available templates** | Already exists; foundation for customization | Done | `list-templates` command | Extend with metadata |
| **Preview template appearance** | Users need to see before choosing | Medium | HTML preview or screenshots | Could be doc links initially |
| **Copy/fork existing template** | Start from working template, not blank | Low | File copy with rename | `scaffold template --from base` |
| **Color customization** | Most common customization request | Low | CSS variables already exist | Expose via wizard or config |
| **Font selection** | Second most common customization | Low | CSS variables | Limited to ATS-safe fonts |
| **Margin adjustment** | Page density preferences | Low | CSS variables already exist | Expose via config |
| **Template validation** | Custom templates should be validated | Medium | Schema for template structure | Catch errors before build |

**Complexity Notes:**
- Color, font, margin are low complexity because CSS variables already exist
- Template validation medium complexity, requires defining template schema

### 3.2 Differentiators

Features that make template customization powerful.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **Guided template wizard** | "What style do you prefer?" questionnaire | Medium | Prompt-driven config generation |
| **Section visibility toggles** | Hide/show optional sections (projects, certs) | Low | Config flags |
| **Section ordering customization** | Reorder sections without editing template | Medium | Config-driven section order |
| **Dark mode support** | Already implemented; extend to new templates | Low | CSS already exists |
| **ATS score preview** | Show estimated ATS compatibility of template | High | Would need scoring engine |
| **Template themes** | Multiple color schemes per template | Low | CSS variable presets |
| **Custom section support** | Add user-defined sections | Medium | Schema extension |

**Differentiator Priority (Recommended):**

**High priority (build first):**
1. Section visibility toggles - quick win
2. Template themes - easy with existing CSS vars
3. Copy/fork existing template - enables experimentation

**Medium priority (build second):**
4. Guided template wizard
5. Section ordering customization
6. Template validation

**Lower priority (consider later):**
7. ATS score preview (requires significant investment)
8. Custom section support

### 3.3 Anti-Features

Things to deliberately NOT build for templates.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| **Multi-column layouts** | ATS parsing issues; explicit anti-feature from v1 | Single-column only |
| **Graphic elements/icons** | ATS cannot parse; accessibility issues | Text-based designs |
| **Custom fonts via upload** | ATS compatibility; file management complexity | Curated font list |
| **WYSIWYG template editor** | Out of scope; massive complexity | Edit files directly |
| **Template marketplace/sharing** | Out of scope; infrastructure | Local templates only |
| **Real-time template preview** | Would need embedded browser; complexity | Generate and view separately |

## 4. UX Patterns and Interactions

### 4.1 AI Command UX Pattern

Recommended interaction pattern for AI features:

```
$ cvgen ai improve johndoe

Analyzing CV for improvements...

Found 3 suggestions:

1. [Experience] Senior Developer at Acme Corp
   Current: "Worked on backend systems"
   Suggested: "Architected and scaled backend systems serving 2M daily users,
              reducing response time by 40%"
   [a]ccept / [e]dit / [s]kip / [q]uit?

2. [Summary] Professional Summary
   Current: "Experienced software engineer with 5 years..."
   Suggested: "Results-driven software engineer with 5+ years building
              high-performance systems at scale..."
   [a]ccept / [e]dit / [s]kip / [q]uit?

Applied 2 changes. Run `cvgen build johndoe` to regenerate.
```

**Key UX Principles:**
1. **Show context** - Which section, what's there now
2. **Show diff** - Exactly what will change
3. **User control** - Accept, edit, skip each suggestion
4. **Batch mode available** - `--yes` to accept all for power users
5. **Non-destructive** - Can always reject changes

### 4.2 Prompt Export UX Pattern

For users without API keys:

```
$ cvgen ai improve johndoe --export

No API key configured. Generating prompt for manual use...

=== PROMPT (copied to clipboard) ===

You are a professional resume writer. Improve the following CV bullet points
to be more impactful using the STAR method and quantifiable achievements.

Current content:
- Worked on backend systems
- Managed team of developers
- Improved code quality

Rewrite each bullet to:
1. Start with a strong action verb
2. Include quantifiable metrics where possible
3. Focus on business impact, not just activities

=== END PROMPT ===

Paste this into ChatGPT, Claude, or your preferred AI assistant.
Then use `cvgen ai apply` to integrate the results.
```

### 4.3 Wizard UX Pattern

Interview-style wizard for adding work experience:

```
$ cvgen wizard add experience johndoe

Adding new work experience to johndoe's CV...

? Company name: Acme Corporation
? Your job title: Senior Software Engineer
? Start date (YYYY-MM): 2022-03
? End date (YYYY-MM or "present"): present
? Location (optional): San Francisco, CA

Let's add your achievements. I'll ask you questions to help craft impactful bullets.

? What was your main responsibility?
> Led the migration of our monolith to microservices

? What was the scale or scope?
> 15 services, 50+ engineers involved

? What was the measurable outcome?
> Deployment frequency increased from monthly to daily, incidents reduced 60%

Generated bullet:
  "Led migration from monolith to 15 microservices with 50+ engineers,
   increasing deployment frequency from monthly to daily and reducing
   production incidents by 60%"

? [a]ccept / [e]dit / [r]egenerate / [s]kip? a

? Add another achievement? (y/n): n

Experience added to johndoe's CV. Run `cvgen build johndoe` to regenerate.
```

**Key UX Principles:**
1. **Progressive disclosure** - One question at a time
2. **Guided extraction** - STAR-method questions
3. **Immediate feedback** - See generated content right away
4. **Easy escape** - Skip questions, exit anytime
5. **Incremental value** - Each answer improves output

### 4.4 Template Customization UX Pattern

```
$ cvgen template customize base --output my-template

Creating custom template based on "base"...

? Primary color (hex or name): #2563eb
? Accent color (hex or name): #1e40af
? Font family: Inter (default), Arial, Calibri, Georgia
> Calibri

? Section visibility:
  [x] Summary
  [x] Experience
  [x] Education
  [x] Skills
  [ ] Projects
  [ ] Certifications
  [ ] Publications

? Section order: (use arrow keys to reorder)
  1. Summary
  2. Experience
  3. Skills
  4. Education

Created template "my-template" at templates/my-template/

Preview: cvgen build johndoe my-template --format html
```

### 4.5 Non-Interactive Fallback Pattern

All wizard features must support non-interactive usage:

```
# Interactive (default when TTY)
$ cvgen wizard add experience johndoe

# Non-interactive via flags
$ cvgen wizard add experience johndoe \
  --company "Acme Corp" \
  --title "Senior Engineer" \
  --start 2022-03 \
  --end present \
  --bullet "Led migration to microservices" \
  --bullet "Reduced incidents by 60%"

# Non-interactive via JSON
$ cvgen wizard add experience johndoe --json-input experience.json

# Detect non-TTY and fail gracefully
$ echo "" | cvgen wizard add experience johndoe
Error: Interactive mode requires TTY. Use --flags or --json-input for non-interactive usage.
```

## 5. Complexity Assessment

### 5.1 AI Features Complexity

| Feature | Complexity | Effort Estimate | Risk Factors |
|---------|------------|-----------------|--------------|
| Basic bullet generation | Medium | 2-3 days | Prompt engineering iteration |
| Summary generation | Low | 1 day | Similar to bullets |
| Multi-provider support | Medium | 3-4 days | Provider API differences |
| Prompt export fallback | Low | 0.5 days | Clipboard only |
| Job description tailoring | High | 5-7 days | JD parsing, matching logic |
| Local Ollama support | Medium | 2-3 days | Ollama API differences |
| Interview-style extraction | High | 5-7 days | Conversational state |

### 5.2 Wizard Features Complexity

| Feature | Complexity | Effort Estimate | Risk Factors |
|---------|------------|-----------------|--------------|
| Basic wizard (init enhancement) | Low | 1-2 days | Inquirer.js handles most |
| Section-specific wizards | Low | 2-3 days | Multiple small wizards |
| Non-interactive fallback | Low | 1 day | Flag parsing |
| Guided achievement prompts | Low-Medium | 2 days | Prompt design |
| Incremental CV updates | Medium | 3 days | Merge logic |
| State persistence/resume | High | 4-5 days | Serialization, edge cases |

### 5.3 Template Features Complexity

| Feature | Complexity | Effort Estimate | Risk Factors |
|---------|------------|-----------------|--------------|
| Copy/fork template | Low | 0.5 days | File operations |
| Color/font customization | Low | 1 day | CSS vars exist |
| Template wizard | Medium | 2-3 days | Prompt flow design |
| Section visibility toggles | Low | 1 day | Config flags |
| Template validation | Medium | 2-3 days | Schema definition |

### 5.4 Recommended Build Order

**Phase A: Foundation (Week 1)**
1. LLM provider abstraction layer
2. Basic prompt templates
3. Prompt export fallback

**Phase B: Core AI (Weeks 2-3)**
4. Bullet generation command
5. Summary generation
6. Improvement suggestions

**Phase C: Wizard Foundation (Week 4)**
7. Enhanced init wizard
8. Add experience wizard
9. Non-interactive fallbacks

**Phase D: Integration (Weeks 5-6)**
10. Job description tailoring
11. Template customization wizard
12. Local model support (Ollama)
