<task type="auto">
  <name>Task 3: Apply CSS fixes if needed</name>
  <files>templates/_shared/partials/_print.css</files>
  <action>
If CSS fixes are needed based on Task 2 analysis:

**Likely fixes (from RESEARCH.md):**

1. **If @page margins differ between browser and CLI**:
   The _print.css should already have:
   ```css
   @page {
     margin: 20mm 0;
   }
   @page :first {
     margin-top: 0;
   }
   ```
   Verify these rules exist and match BROWSER_PDF_OPTIONS.

2. **If content overflows differently**:
   Check that all containers have proper width constraints:
   ```css
   @media print {
     main,
     .cv-container {
       max-width: 100%;
       overflow: hidden;
     }
   }
   ```

3. **If break properties work differently**:
   Browser print should respect the existing break rules from Phase 11.
   If not, ensure legacy properties are present:
   ```css
   .entry {
     break-inside: avoid;
     page-break-inside: avoid;  /* Legacy for browser compat */
   }
   ```

**If no CSS fixes are needed**:
- Skip this task
- The existing CSS from Phase 10-11 should work for browser print

**If differences are due to CLI two-pass redistribution**:
- This is NOT a CSS fix - it's expected behavior
- The CLI PDF may have 1 fewer page due to redistribution optimization
- Document this as a known limitation, not a failure
  </action>
