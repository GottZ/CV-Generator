<task type="auto">
  <name>Task 1: Add flexbox-to-block conversions for print</name>
  <files>templates/_shared/partials/_print.css</files>
  <action>
Add CSS rules inside the existing `@media print` block to convert flexbox containers to block display. This is REQUIRED because CSS break properties are ignored on flex items.

Add the following rules after the existing `.contact` rules (around line 71):

```css
  /* === Flexbox-to-Block Conversion (required for break properties) === */
  /* Main content area */
  main {
    display: block;
  }

  /* Contact info row */
  .contact-info {
    display: block;
  }

  .contact-item {
    display: inline;
    margin-right: 8px;
  }

  .contact-item:not(:last-child)::after {
    content: ' | ';
    margin-left: 8px;
  }

  /* Entry header (title + date) */
  .entry-header {
    display: block;
  }

  .entry-title {
    display: inline;
  }

  .date-range {
    display: inline;
    float: right;
  }

  /* Skill lists */
  .skill-list {
    display: block;
  }

  .skill {
    display: inline;
    margin-right: 8px;
  }

  /* Tech stack tags */
  .tech-stack {
    display: block;
  }

  .tech-tag {
    display: inline;
    margin-right: 8px;
  }

  /* Project links */
  .project-links {
    display: block;
  }
```

Key points:
- Override `display: flex` with `display: block` on containers
- Child items become `display: inline` with margin for spacing
- Use `float: right` on `.date-range` to maintain right-alignment
- This enables `break-inside: avoid` to work correctly on entries
  </action>

Confirm: CSS rules for flexbox conversion are present
  </verify>
  <done>
Flexbox containers (.contact-info, .entry-header, .skill-list, .tech-stack, .project-links, main) are converted to block display within @media print, enabling break properties to function correctly.
  </done>

<task type="auto">
  <name>Task 2: Add entry-type specific pagination rules</name>
  <files>templates/_shared/partials/_print.css</files>
  <action>
Add explicit pagination rules for all entry types. The existing `_print.css` has generic `.entry` rules but is missing specific entry type selectors.

Add after the flexbox conversion rules (Task 1):

```css
  /* === Entry-Type Specific Pagination === */
  /* All entry types are atomic units - never break inside */
  .experience-entry,
  .education-entry,
  .project-entry,
  .certification-entry {
    break-inside: avoid;
    page-break-inside: avoid;
  }

  /* Entry headers stay with content that follows */
  .entry-header {
    break-after: avoid;
    page-break-after: avoid;
  }
```

The existing `.entry` rule already handles the base case, but explicit selectors ensure templates with entry-type-specific classes also get pagination protection.

Note: Do NOT add `break-inside: avoid` to `.section` - sections SHOULD be allowed to span pages. Only individual entries within sections are atomic.
  </action>

Confirm: All four entry type selectors appear in print CSS with break-inside: avoid
  </verify>
  <done>
All entry types (experience, education, project, certification) have explicit break-inside: avoid rules, ensuring no entry splits across page boundaries.

<task type="auto">
  <name>Task 3: Add orphan/widow control for text elements</name>
  <files>templates/_shared/partials/_print.css</files>
  <action>
Add orphan/widow control to prevent isolated lines at page boundaries. Per CONTEXT.md: "Section headers need at least 2 lines of content before a page break is allowed."

Add after the entry-type pagination rules:

```css
  /* === Orphan/Widow Control === */
  /* Prevent isolated lines at page boundaries */
  p,
  .summary-text,
  .project-description,
  .entry-notes {
    orphans: 2;
    widows: 2;
  }

  /* Section content needs minimum lines with header */
  .section > *:first-child {
    orphans: 2;
    widows: 2;
  }
```

Key points:
- `orphans: 2` = minimum 2 lines at bottom of page before break
- `widows: 2` = minimum 2 lines at top of page after break
- These are browser hints, not strict rules - browser will do its best
- Firefox does not support these properties (but we use Puppeteer/Chromium)

Note: The existing `.section { orphans: 3; widows: 3; }` rule is already present but applies to the section container, not the text content. The new rules target actual text elements.
  </action>

Text elements (paragraphs, summaries, descriptions) have orphans: 2 and widows: 2 rules, preventing single isolated lines at page boundaries.
  </done>
